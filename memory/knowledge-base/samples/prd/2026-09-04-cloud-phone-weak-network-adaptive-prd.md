## 1. 背景

### 1.1 业务背景
云手机业务中，用户通过公网访问云端 Android 实例，视频流实时传输到终端。弱网环境下（带宽不足、抖动、丢包），视频卡顿、花屏、延迟高的问题严重影响用户体验。

### 1.2 问题描述
当前云手机视频流在弱网环境下缺乏智能自适应能力，主要依靠固定码率和简单缓冲，无法根据网络状况动态调整画质。

### 1.3 目标与价值
- 提升弱网环境下的用户体验
- 降低视频卡顿率和卡顿时长
- 为不同终端提供差异化画质

---

## 2. 范围

### 2.1 功能范围
- 网络质量实时监测（带宽、延迟、丢包、抖动）
- 弱网自适应降档（分辨率、帧率、码率）
- 多终端 Simulcast 分层输出
- 流媒体网关智能选层转发
- 网络恢复后自动回升画质

### 2.2 不在范围内
- 音频自适应（本次仅做视频）
- 云端 Android 系统层改造
- 终端解码能力外的硬件适配

### 2.3 影响范围
- 云手机视频编码模块
- 流媒体网关
- 客户端播放器
- 监控与告警平台

---

## 3. 用户故事

- 作为云手机用户，我希望在弱网环境下仍然能流畅操作云手机，避免卡顿和花屏。
- 作为云手机产品经理，我希望系统能根据用户网络自动调整画质，平衡体验与成本。

## 4. 功能需求

| 编号 | 功能点 | 描述 | 优先级 |
|------|--------|------|--------|
| F1 | 网络质量监测 | 实时采集 RTT、丢包率、带宽、抖动 | P0 |
| F2 | 带宽估计 | 基于 GCC 估算可用带宽 | P0 |
| F3 | 动态码率控制 | 根据带宽动态调整编码码率 | P0 |
| F4 | Simulcast 编码 | 云端输出多路不同质量视频流 | P0 |
| F5 | 智能选层 | 网关根据接收端带宽选层转发 | P0 |
| F6 | 画质回升 | 网络恢复后平滑回升画质 | P1 |
| F7 | 降级兜底 | 极端弱网下切换到低帧率或静态画面 | P1 |
| F8 | 监控大盘 | 展示弱网自适应触发次数、卡顿率、画质分布 | P2 |

---

## 5. 非功能需求

| 维度 | 需求 |
|------|------|
| 性能 | 端到端延迟 < 200ms |
| 可用性 | 自适应策略可用性 >= 99.9% |
| 兼容性 | 支持主流浏览器和云手机客户端 |
| 安全 | 不引入新的安全风险 |
| 可观测 | 关键指标可监控、可告警 |

---

## 6. 技术方案建议

- 编码侧：云端 Android 实例集成 WebRTC 编码器，输出 Simulcast 多路流
- 传输侧：流媒体网关基于 BWE 和 RTCP 反馈做智能选层
- 客户端：根据终端能力和网络状况选择合适层级
- 控制侧：引入 GCC 拥塞控制 + 自适应码率算法

---

## 7. 验收标准

| 编号 | 验收条目 | 验证方式 |
|------|----------|----------|
| A1 | 弱网场景卡顿率下降 >= 40% | 弱网模拟测试 |
| A2 | 层间切换延迟 < 100ms | 实验室测试 |
| A3 | Simulcast 覆盖主流浏览器 | 兼容性测试 |
| A4 | 监控指标完整可采集 | 监控平台核对 |

---

## 8. 风险与依赖

| 风险 | 影响 | 应对策略 |
|------|------|----------|
| 云端 CPU 开销增加 | 单实例并发能力下降 | GPU 编码加速，限制层数 |
| 层间切换卡顿 | 用户体验下降 | 关键帧缓冲和切换防抖 |
| 终端兼容性问题 | 部分用户无法使用 | 动态协商，回退策略 |
