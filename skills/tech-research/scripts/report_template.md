# 技术调研报告模板

按以下结构输出调研报告，每个章节不可省略。

---

## 报告结构

```markdown
# 【技术调研】{调研主题}

> 调研人：{姓名/AI}
> 调研日期：{YYYY-MM-DD}
> 关键词：{关键词1, 关键词2, ...}

---

## 一、背景与目标

### 1.1 调研背景
为什么要调研这个技术？当前面临什么问题？

### 1.2 调研目标
希望通过调研回答哪些问题？（列出 2-3 个核心问题）

---

## 二、技术概述

### 2.1 核心概念
用通俗的语言解释这个技术是什么。

### 2.2 技术原理
关键原理、协议、算法说明。可配图或代码示例。

### 2.3 发展现状
当前版本、社区活跃度、主流厂商采用情况。

---

## 三、方案对比

| 维度 | 方案A | 方案B | 方案C（可选） |
|------|-------|-------|---------------|
| 原理 | | | |
| 优点 | | | |
| 缺点 | | | |
| 适用场景 | | | |
| 成熟度 | | | |
| 社区/厂商支持 | | | |
| 落地成本 | | | |

---

## 四、落地建议

### 4.1 推荐方案
结合云手机场景，推荐哪个方案，理由是什么。

### 4.2 实施路径
分几步落地？每步的核心工作是什么？

### 4.3 预期收益
落地后能带来什么效果（量化优先）。

---

## 五、风险与局限

- 风险1：...
- 风险2：...
- 局限：...

---

## 六、参考资料

| 序号 | 标题/描述 | 来源 | URL |
|------|-----------|------|-----|
| 1 | | | |
| 2 | | | |
| ... | | | |
```

---

## 格式要求

- 方案对比必须用表格，直观易读
- 事实性陈述标注来源（如"据 WebRTC 官方文档..."）
- 落地建议必须结合云手机实际场景
- 参考资料必须包含可访问的 URL
- 报告总长度建议 2000-4000 字
