# PRD 生成智能体

面向云手机产品研发的需求文档生成 Skill，支持从零散需求要点到标准 PRD 的自动转化，并接入 RAG 检索历史 PRD 保证格式与术语一致。

## 触发场景

用户提到以下意图时触发：
- "写 PRD"、"生成需求文档"、"写需求说明书"
- "帮我整理一下需求"、"把这个需求文档化"
- "做一个 XX 功能的需求分析"

## 工作流程

### 1. 收集需求输入

明确用户输入中的关键要素：
- **背景/问题**：为什么做这个需求？
- **目标/价值**：解决谁的什么问题？
- **功能范围**：包含哪些功能点？
- **非功能需求**：性能、稳定性、安全、合规等
- **限制条件**：排期、资源、依赖
- **参考/竞品**：是否有可参照的现有方案

### 2. 检索历史 PRD（RAG）

用 `exec` 执行 curl 调用 Dify 检索 API：
```bash
curl -s -X POST "${DIFY_API_BASE}/v1/datasets/${DIFY_DATASET_ID}/retrieve" \
  -H "Authorization: Bearer ${DIFY_API_KEY}" \
  -H "Content-Type: application/json" \
  -d '{"query":"<模块关键词> PRD 需求文档","top_k":5}'
```
检索：
- 同类型/同模块的历史 PRD
- 云手机术语与规范（协议、架构、命名）
- 相似功能的风险点与验收标准

> 如果 Dify 不可用，降级到本地 `memory_search`。

### 3. 生成 PRD

按模板结构输出（详见 `scripts/prd_template.md`），必填项：

| 章节 | 说明 |
|------|------|
| 1. 背景 | 业务背景、问题描述、目标价值 |
| 2. 范围 | 功能范围、不在范围内、影响范围 |
| 3. 用户故事 | 至少 1 个用户故事（角色-场景-收益） |
| 4. 功能需求 | 用编号列出的功能点，可含优先级 P0/P1/P2 |
| 5. 非功能需求 | 性能、可用性、安全、兼容、合规 |
| 6. 技术方案建议 | 关键技术点、接口/协议、依赖 |
| 7. 验收标准 | 可测试的验收条目 |
| 8. 风险与依赖 | 风险、依赖方、应对策略 |
| 9. 附录 | 原型/参考链接/术语表 |

### 4. 变更追踪（可选）

如果用户提供了旧版本 PRD 或要求对比：
- 读取旧版本 PRD
- 生成变更清单（新增/修改/删除）
- 输出 diff 摘要和变更记录表

### 5. 归档

- 保存到 `memory/knowledge-base/samples/prd/`
- 文件名：`YYYY-MM-DD-<模块名>-PRD.md`
- 更新 `memory/knowledge-base/INDEX.md`

## 输出规范

- 使用 Markdown 表格呈现功能清单和验收标准
- 所有技术术语与云手机现有规范保持一致
- 明确优先级和验收标准，避免模糊描述
- 变更追踪时标注版本号和变更日期
