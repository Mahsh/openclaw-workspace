# Git 提交总结智能体

面向云手机研发的代码变更总结 Skill。核心能力：**分析本地代码仓库任意两次提交之间的修改**，输出结构化变更总结、影响面分析与风险提示。

支持三种对比模式：
1. **两次提交之间**（主场景）：`git diff <commit1>..<commit2>`
2. **分支对比**：`git diff <base-branch>..<head-branch>`
3. **工作区改动**：`git diff`（未提交的改动）

## 触发场景

用户提到以下意图时触发：
- "总结一下这两个 commit 之间的改动"、"看看从 A 到 B 改了什么"
- "总结一下这个分支的改动"
- "生成 change summary"、"写提交说明"
- "这个 PR 改了什么"、"帮我 review 一下改动"
- "批量总结一下最近几个分支"

## 执行准备

1. **确认仓库路径**：用户未指定时，先用 `git rev-parse --show-toplevel` 确认当前目录在仓库内；用户指定了其他路径则所有 git 命令加 `-C <repo-path>`
2. **确认对比范围**：
   - 用户给了两个 commit（或 tag / SHA / HEAD~N）→ `git diff <A>..<B>`
   - 用户只说"最近的改动"且未给范围 → 先 `git log --oneline -10` 列出候选提交，请用户确认起点终点
   - 严禁自行猜测对比基线做批量分析

## 工作流程

### 1. 收集 Git 信息

统一用 `exec` 执行（`<A>`、`<B>` 为对比的两端）：

| 用途 | 命令 |
|------|------|
| 仓库根目录 | `git rev-parse --show-toplevel` |
| 当前分支 | `git branch --show-current` |
| 提交区间列表 | `git log <A>..<B> --oneline --no-merges` |
| 提交区间统计 | `git diff <A>..<B> --stat` |
| 变更文件清单 | `git diff <A>..<B> --name-status` |
| 完整 diff | `git diff <A>..<B>`（大仓库先按文件过滤，见下） |
| 单文件 diff | `git diff <A>..<B> -- <path>` |

**大仓库控制输出量的规则**：
- 变更文件数 > 30 时，先只取 `--stat` + `--name-status`，再对核心业务文件逐个 `git diff -- <path>`
- 跳过二进制与锁文件：`-- . ':(exclude)*.lock' ':(exclude)*.min.js' ':(exclude)dist/*'`
- 单个文件 diff 超过 500 行时，只读关键 hunk（新增函数、接口定义、配置项），并在总结中注明"该文件较大，仅分析关键改动"

**上下文补充（可选）**：若用户提到相关需求/PRD，用 `dify-rag` skill 检索对应背景，写入"关联信息"章节。

### 2. 分析变更

按规则识别影响面（五层）：

- **协议层**：protobuf、Thrift、RPC 定义、API 路由、消息格式、字段增删改
- **业务层**：业务逻辑、状态机、核心流程、算法、边界条件
- **配置层**：配置文件、开关、环境变量、默认值、超时/重试参数
- **基础设施层**：CI/CD、构建脚本、依赖版本、容器与部署清单
- **文档层**：README、设计文档、API 文档、注释

统计信息（取自 `--stat` 汇总行）：
- 提交数（`--oneline --no-merges` 行数）
- 新增/修改/删除文件数（`--name-status` 中 A / M / D）
- 新增/删除行数
- 涉及模块数（按顶层目录聚合）

### 3. 生成总结

按 `scripts/summary_template.md` 模板输出（先读模板，逐节填充，勿自行增删章节）：

1. **基本信息**：分支、对比基线（**写明 A 与 B 的 SHA 短号与提交标题**）、提交数、变更文件数、增删行数
2. **核心改动摘要**：3~8 条，每条一句话说清"改了什么 + 为什么"，按影响大小排序
3. **影响面分析**：五层表格，无涉及的层填"无"
4. **风险提示**：表格形式，每条含「风险 + 描述 + 建议」，重点关注：接口不兼容、默认值变更、数据迁移、并发与超时、权限与鉴权
5. **评审建议**：可执行的 review 关注点（必须重点看哪几个文件、建议补哪些测试）
6. **关联信息**：相关需求/PRD、相关技术方案、相关提交

### 4. 批量总结

对多个分支或多段提交区间：
- 逐个执行单次总结（可并行，用子 Agent 分担）
- 汇总为表格：范围、核心改动、影响面、风险等级（高/中/低）

### 5. 归档

- 保存到 `sync_files/git-summaries/`（该目录经 GitHub 同步，多端可见）
- 文件名：`YYYY-MM-DD-<A短号>-to-<B短号>-change-summary.md`
- 若 `memory/knowledge-base/INDEX.md` 存在，追加一行索引记录

## 输出规范

- 必须包含影响面五层分析（无涉及的层写"无"，不留空）
- 风险必须有「描述 + 应对建议」
- 行数统计必须来自 `git diff --stat`，不得估算
- 基本信息中必须写清对比两端的具体 commit，保证可复现
- 多段区间时输出汇总表格
