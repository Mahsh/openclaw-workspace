## 1. 背景

### 1.1 业务背景

云手机是将手机操作系统运行在云端，通过网络将画面实时传输到终端用户设备的云端服务。其核心技术链路可以抽象为：

```
云端 Android 实例 --(视频编码)--> 流媒体网关 --(网络传输)--> 用户终端
```

在这个链路中，**网络质量直接决定了用户体验**。弱网环境下（带宽不足、抖动、丢包），视频流可能出现卡顿、花屏、延迟高等问题。

### 1.2 核心问题

- 如何在弱网环境下快速、平滑地降低视频质量，保障交互连续性？
- 如何在网络恢复后快速回升画质，避免过冲？
- 如何在云手机单实例多用户、多分辨率的复杂场景下做自适应？

### 1.3 调研目标

1. 梳理 WebRTC 弱网自适应的核心技术原理
2. 对比主流 QoS 降档方案（动态码率控制、Simulcast、SVC）
3. 结合云手机场景给出可落地的推荐方案
4. 识别实施风险与关键技术指标

## 2. 技术概述

### 2.1 WebRTC 核心 QoS 机制

| 机制 | 说明 | 作用 |
|------|------|------|
| GCC | Google Congestion Control | 基于延迟梯度的带宽估计 |
| BWE | Bandwidth Estimation | 估算可用带宽 |
| Simulcast | 同时编码多路不同质量流 | 接收端/SFU 按需选层 |
| SVC | Scalable Video Coding | 单流分层编码，按层丢弃 |
| TMMBR/TSTR | RTCP 反馈消息 | 请求发送端调整码率/质量 |
| DSCP | 分组优先级标记 | 网络层 QoS |

### 2.2 云手机场景的特殊性

| 特点 | 影响 |
|------|------|
| 实时交互强 | 触控、滑动、输入需要低延迟回传 |
| 画面变化剧烈 | 游戏、视频、应用切换导致码率波动大 |
| 单实例共享 | 多用户/多屏场景下带宽与 CPU 资源竞争 |
| 终端差异大 | 手机、PC、TV 等不同终端的解码和显示能力不同 |
| 网络环境复杂 | 公网、WiFi、4G/5G、企业内网混合 |

## 3. 方案对比

| 维度 | 方案 A：动态码率控制 | 方案 B：Simulcast | 方案 C：SVC |
|------|-------------------|-----------------|-----------|
| 实现复杂度 | 低 | 中 | 中高 |
| 带宽利用率 | 高 | 中（多路编码开销） | 中高 |
| 弱网降档平滑度 | 平滑 | 可能有跳变 | 平滑 |
| 多终端适配 | 差 | 好 | 好 |
| 对 SFU 要求 | 低 | 中 | 高 |
| CPU 开销 | 低 | 高 | 中 |
| 浏览器兼容性 | 最好 | 好 | 有限 |
| 推荐场景 | 1v1、简单场景 | 多人、多终端 | 大规模、可控终端 |

### 3.1 方案优劣势分析

**方案 A：动态码率控制**
- 优势：实现简单、带宽利用率高、兼容性好
- 劣势：单流质量跳变明显，难以为不同终端差异化服务

**方案 B：Simulcast**
- 优势：多终端按需选层、切换快速、生态成熟
- 劣势：发送端编码和上行带宽开销大

**方案 C：SVC**
- 优势：单流分层、带宽效率优于 Simulcast、平滑降档
- 劣势：浏览器/终端支持有限，SFU 实现复杂

## 4. 落地建议

### 4.1 推荐方案

**云手机场景推荐：Simulcast + 动态码率控制组合方案**

原因：
1. 云手机用户终端多样，Simulcast 可为不同终端提供差异化质量
2. 动态码率控制作为兜底，在 Simulcast 最低层仍不足时继续降档
3. 生态成熟，主流浏览器和 SFU 均支持
4. 渐进可演进，未来可引入 SVC 进一步优化

### 4.2 云手机落地关键点

| 关键点 | 建议 |
|--------|------|
| 编码层 | 云端 Android 实例输出多路 Simulcast 流（如 360p/720p/1080p） |
| 传输层 | 流媒体网关根据接收端带宽智能选层转发 |
| 控制层 | 集成 GCC/BWE，实时监测 RTT、丢包率、抖动 |
| 终端层 | 根据终端解码能力和屏幕尺寸选择合适层级 |
| 兜底策略 | 极端弱网下切换到静态画面或降低帧率 |

### 4.3 关键技术指标

| 指标 | 目标值 |
|------|--------|
| 端到端延迟 | < 200ms |
| 弱网卡顿率 | 较基线下降 40%+ |
| 首帧时间 | < 1s |
| 层间切换时延 | < 100ms |
| 带宽利用率 | 较单流方案提升 15%+ |

## 5. 风险与局限

| 风险 | 影响 | 应对 |
|------|------|------|
| Simulcast 多路编码增加云端 CPU 负载 | 单实例并发能力下降 | 限制层数，云端 GPU 编码加速 |
| 层间切换卡顿 | 用户体验下降 | 切换前请求关键帧，优化缓冲 |
| 网络波动导致频繁切换 | 画质忽好忽坏 | 引入切换滞后和防抖策略 |
| 终端不支持 Simulcast | 部分用户无法受益 | 动态协商，回退到单流动态码率 |
