# 云应用跳转外链或应用消息传输文档

## 1 需求背景

### 1.1 业务现状

云应用架构：**云端运行云OS与云化Android应用，端侧使用H5页面承载展示，H5集成JSSDK，JSSDK负责端‑云之间消息通信**。
云OS内云化应用经常会产生跳转行为：包含跳转外部H5链接、拉起第三方App（微信、支付宝、系统设置页、应用市场等）。

> 
> 限制：云OS运行在云端虚拟环境，一般只安装目标云化应用,**云化应用无法直接拉起三方应用、无法直接打开目标云化应用的外部链接**。如果直接执行跳转，会出现跳转无响应、行为失效。

### 1.2 业务问题

1. 云化应用内部触发跳转第三方页面/第三方App时，端侧H5无感知，点击跳转无效果，用户操作失效。
2. 跳转失败场景缺少弹窗提示，用户不清楚操作为什么不生效，体验差。

### 1.3 业务目标

1. 云OS内云化应用产生跳转行为时，通过端云消息通道，将跳转指令传递到端侧H5，由H5在真实设备环境完成跳转逻辑。
2. 区分两种跳转类型：跳转网页链接`jumpurl`、拉起第三方应用`jumpapp`。
3. 增加白名单校验，仅允许白名单内链接；不在白名单内拦截跳转。
4. 跳转能力异常、不支持跳转场景，弹出友好提示弹窗告知用户。
5. 定义统一消息协议`code=6110`，JSSDK负责透传消息，H5解析并执行业务跳转。

## 2 整体架构与业务流程

### 2.1 架构简述

- **云OS（云端）**：运行云化Android应用；云化应用发生跳转行为，封装成`code=6110`消息，传递给端侧JSSDK。
- **JSSDK（端侧）**：端‑云消息中转层；接收云端下发消息，识别`code=6110`，将完整消息体透传给上层H5，不做业务解析。
- **H5页面（端侧）**：接收JSSDK透传的6110消息，解析`apptype`、`appmessage`，完成白名单校验，执行跳转逻辑；校验失败/不支持跳转展示提示弹窗。

### 2.2 完整业务流程

1. 云端云OS内部云化应用触发跳转行为（跳转网页/拉起第三方App）。
2. 云OS将跳转信息封装为消息，消息`code=6110`，携带`apptype`、`appmessage`，通过端云通道下发至端侧JSSDK。
3. JSSDK收到`code=6110`消息，**不对消息体做业务解析，完整透传消息对象给到上层H5页面**。
4. H5接收6110消息，解析字段：
   - `apptype = jumpurl`：网页链接跳转场景；`appmessage`包含包名、目标跳转URL地址。
   - `apptype = jumpapp`：拉起第三方App场景；`appmessage`包含目标App包名。
5. H5读取本地维护的跳转白名单：
   - ✅校验通过：端侧H5调用系统能力，执行对应跳转。
   - ❌校验不通过：拦截跳转，点击无响应，不执行跳转动作。
6. 云应用不支持跳转第三方，触发弹窗提示“云应用体验模式下暂不支持跳转至其他应用”。

> 
> 业务流程图简版：
> 云OS云化应用 → 组装6110消息下发 → JSSDK透传消息 → H5解析apptype/appmessage → 白名单校验 → {校验通过：执行跳转；校验失败：拦截不跳转}

## 3 消息协议定义（code=6110）

### 3.1 消息基础结构

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| code | Number | 消息类型固定：**6110**，代表第三方跳转透传消息 |
| data | Object | 消息业务载体 |
| data.apptype | String | 跳转类型枚举值：   `jumpurl`：跳转网页链接   `jumpapp`：拉起第三方App |
| data.appmessage | Object | 跳转业务参数，根据apptype不同内部字段含义不同 |

#### 3.1.1 apptype = jumpurl（网页跳转）

```
{
  "code": 6110,
  "data": {
    "apptype": "jumpurl",
    "appmessage": {
      "packageName": "目标源应用包名",
      "jumpUrl": "https://xxx.xxx.com/target"
    }
  }
}
```

- packageName：云OS内触发跳转的源应用包名；
- jumpUrl：需要在端侧打开的网页链接地址，H5使用该URL做白名单匹配。

#### 3.1.2 apptype = jumpapp（拉起第三方App）

```
{
  "code": 6110,
  "data": {
    "apptype": "jumpapp",
    "appmessage": {
      "packageName": "目标第三方App包名",
    }
  }
}
```

- packageName：待拉起的第三方应用包名；

## 4 JSSDK处理逻辑

> 
> JSSDK职责：消息路由透传，**不参与业务逻辑解析、不做白名单校验、不执行跳转**。

1. JSSDK监听来自云端OS下发的消息事件；
2. 判断消息`code === 6110`；
3. 如匹配6110，将完整原始消息对象，通过JS事件回调透传给上层H5页面；
4. JSSDK不修改`apptype`、`appmessage`内容，原样输出；
5. 非6110消息走原有其他消息处理逻辑。

H5订阅JSSDK抛出的事件，接收code=6110消息，执行业务解析、白名单校验、跳转、异常弹窗。

## 6 接口与兼容性说明

1. 向下兼容：老版本JSSDK不识别6110消息，消息不会透传到H5，跳转行为失效；需要升级JSSDK版本支持该消息类型。
2. 字段扩展：未来新增字段，在`appmessage`内扩展，不改变外层code=6110结构。
3. 安全注意：云端下发消息需要校验来源，防止伪造6110恶意跳转消息。

## 7 联调要点

1. 云端云OS侧：构造code=6110的测试消息，分别构造jumpurl、jumpapp两种类型；
2. JSSDK：确认6110消息完整透传到H5，没有字段丢失；
3. H5：分别测试白名单命中、白名单不命中、验证跳转/拦截/弹窗；
4. 边界case：空apptype、appmessage字段为空，确认不会产生异常跳转。
